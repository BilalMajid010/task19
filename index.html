10 / ENGINEERING

CSS architecture

Organized layers and modular SCSS make the system easier to extend.

01

Abstracts

Tokens, functions, mixins and shared Sass helpers. No CSS output should be generated here unless intentionally needed.

abstracts/_tokens.scss
02

Base

Reset rules, document defaults, typography and global element styling.

base/_reset.scss · base/_typography.scss
03

Layout

Page-level structure such as the header, sidebar, grid and content container.

layout/_header.scss · layout/_sidebar.scss
04

Components

Independent, reusable UI patterns using BEM naming and limited selector nesting.

components/_buttons.scss · components/_cards.scss
05

Themes & utilities

Theme-specific semantic values and small helper classes.

themes/_themes.scss · utilities/_utilities.scss

Isolation concepts

CSS Modules: build tooling scopes class names to a module to reduce naming collisions.

Shadow DOM: encapsulates a component's DOM and styles. Global selectors generally do not cross its boundary.

Custom properties: inherited CSS variables can pass theme values into components and shadow trees.

Responsive strategy

Media queries are suitable for page layout changes and device preferences such as reduced motion.

Container queries are suitable when a reusable component changes based on the space available to it, regardless of viewport width.

@supports detects browser feature support before applying enhanced styles.

11 / GUIDELINES

Usage & documentation

Shared rules help teams use components consistently.

Naming convention

Use BEM: .block__element--modifier. A block is a standalone component, an element belongs to that block, and a modifier changes its appearance or state.

Component states

Document default, hover, focus-visible, active, disabled, loading, success and error states where relevant. Never rely on color alone to communicate meaning.

Maintainability rules

  • Prefer design tokens over arbitrary values.
  • Avoid unnecessary !important and high-specificity selectors.
  • Keep nesting shallow and selectors independent.
  • Remove unused rules and avoid duplicate declarations.
  • Use semantic HTML and accessible labels.

Feature detection example

@supports (display: grid) {
  .layout { display: grid; }
}

Container query example

.card-container { container-type: inline-size; }
@container (min-width: 32rem) {
  .profile-card { grid-template-columns: auto 1fr; }
}

Entry transition example

.dialog[open] {
  opacity: 1;
  @starting-style { opacity: 0; }
}
